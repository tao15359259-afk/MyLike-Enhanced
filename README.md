# MyLike-Enhanced

把抖音「喜欢」与「收藏」视频列表**完整保存到本地**，随时筛选、搜索、洗牌播放——不依赖抖音 App，几万条内容也能流畅浏览。

> **MyLike-Enhanced** 是基于 [Hannah2227/MyLike](https://github.com/Hannah2227/douyin-favorite-MyLike)（MIT License）的深度改造版：在原版"喜欢列表采集 + 洗牌播放"的基础上，新增**收藏列表全链路采集**与**采集前深度探测 / 卡页自动分段跳坑**，核心目标是大体量账号（十万级列表）的可靠采集。遵循 MIT License 开源，版权声明见 LICENSE。

## Enhanced 版新增能力（相对原版 v1.0.7）

### ★ 收藏列表全链路采集（v1.0.8）
- 与"喜欢"**完全同构**的收藏采集：预检探针 → 两阶段翻页（头部增量 + 断点续尾）→ 增量去重 → 风控状态机 → 断点落盘，全链路按数据源平行复用
- 走 `listcollection` 接口（POST、游标在表单体），无需 sec_user_id，签名仍由页面拦截器自动补齐（零逆向）
- 界面侧栏「喜欢 / 收藏」双源切换；筛选、播放、选择、删除、导出、导入全部跟随当前视图
- 收藏数据独立存储（`collection.dylist`），与喜欢列表互不干扰；断点游标分源记录
- 取消点赞仅作用于喜欢视图（收藏视图隐藏入口 + 宿主双保险拒绝）

### ★ 先探测再加载（v1.0.9）
大体量账号（10 万+ 条）采集前的"地形预演"，10-20 条最小开销请求、约 15 秒摸清接口边界：
- **显示数拉取**：主页累计计数（favoriting_count 等），与预估可采数对比，差值 = 已删除/私密量
- **可达边界定位**：喜欢域按时间戳倍增跳跃（7→3584 天）+ 二分收口；收藏域按数字游标阶梯试探
- **可采数量外推**：三点密度采样（count=18）外推全量条数，采集前先知道结局
- **分段自动跳坑**：可采量超过单段容量（3000 条）时自动生成分段计划；翻页游标卡住（stalled）不再干等收尾——按计划自动跳到下一个分段起点继续硬翻，直到采完或段耗尽
- 探测失败绝不阻塞采集（自动降级为常规盲翻流程）

## 原版能力（保留自 MyLike v1.0.7）

### 采集
- 一键抓取完整「喜欢」列表（标题 / 作者 / 发布时间 / 封面 / 类型）
- 增量采集：再次采集只补新内容，自动去重，翻到断点即停
- 断点续采：中途失败 / 限流 / 手动停止后，从上次进度继续，不遗漏不重复
- 超长列表自动分轮：单轮 200 页（约 3600 条）到上限后自动接着采，进度条显示「第 N 轮」
- 风控自愈：接口被限自动暂停并提示，完成滑块验证后自动断点续采

### 播放
- **先出画面再取链**：点播放立刻打开播放页，随后实时获取播放地址（1~2 秒），链接不落盘、每次都是新鲜的
- 洗牌播放：随机播放当前筛选范围；点卡片可从该条开始顺序播放
- **继续上次播放**：手动退出或直接关闭应用，下次提示「上次播放到…」一键续播
- 实况（动图）图集、图文帖轮播、背景音乐、倍速播放、播放队列、快捷键
- 原页看评论：一键跳转抖音原视频页，关闭后从记忆进度续播

### 批量取消点赞
- 选择模式勾选后逐条在抖音侧取消；自动节流，触发风控自动暂停，完成滑块验证后可续跑

### 数据管理
- 多维筛选：分类 + 年份 + 月份 + 标题作者搜索
- `.dylist` 导入 / 导出备份（合并式导入，多账号内容汇总零成本）

## 快速上手

1. **登录**：点左下角账号区 → 弹窗内完成抖音登录（支持扫码）→ 成功自动关窗
2. **切源**：侧栏顶部「❤ 喜欢 / ★ 收藏」切换数据源
3. **采集**：点仪表盘右侧红色「采集」按钮 → 自动先探测可采范围（约 15 秒，toast 显示预估条数与分段计划）→ 自动开始采集，进度条实时显示
4. **播放**：点任意卡片顺序播放；或「洗牌播放」随机播放当前筛选结果

> **注意**：点赞/收藏上万的账号可能触发接口限流。v1.0.9 会在采集前先探测边界并按分段计划自动跳坑；若仍遇风控，完成滑块验证后自动断点续采。

## 数据与隐私

- **全部数据在本机** `%LOCALAPPDATA%\DouyinShuffle\`，按账号分目录：

  ```
  accounts.json                 账号清单
  settings.json                 应用级设置（主题）
  init.log                      运行日志
  Data\<账号>\items.dylist       喜欢列表（仅元数据）
  Data\<账号>\collection.dylist  收藏列表（仅元数据；Enhanced 新增）
  Data\<账号>\state.json         双源采集断点 / 账号标识
  Data\<账号>\resume.json       上次播放位置
  Profiles\<账号>\              WebView2 用户目录（该账号的登录态）
  ```

- **播放链接不落盘**：链接有时效，播放时实时获取
- **不上传任何服务器**：数据与登录信息全部留在本机

## 技术架构

- **宿主**：WPF（.NET 10）+ WebView2，界面与播放器均为本地网页（嵌入程序集）
- **核心机制「浏览器即签名器」**：所有抖音接口请求都在一个屏幕外的隐藏抖音页中执行，由页面自身签名层自动补齐参数——不做任何逆向，抖音改版容错率高
- **Enhanced 双源架构**：`CollectSource`（Like/Collection）贯穿编排器 / 采集器 / 存储 / UI；各源独立注入脚本、独立探针、独立断点游标、独立存储文件
- **统一风控状态机**：Normal → RiskHeld → Verifying，各场景统一上报与恢复
- **统一响应分类器**：所有脚本共用六形态判定（有效 JSON / 验证页 / 黑洞 / 假数据 / 接口报错）
- **深度探测**：时间跳跃 + 二分收口 + 密度外推（like）；游标阶梯试探（collection）

## 常见问题

- **采集数量比抖音显示的少？** v1.0.9 采集前会自动探测并告知预估可采数：差值主要是已删除 / 私密 / 下架的内容，接口不再返回，少几千到几万条都属正常现象。
- **采集太慢 / 卡在某个位置？** v1.0.9 遇游标停滞会按探测生成的分段计划自动跳坑续采；若触发风控会暂停提示，稍后再点「采集」自动断点续采。
- **喜欢和收藏数据混在一起吗？** 不。两域独立存储、独立断点、独立导出导入文件（.dylist 格式互通，可按需合并）。
- **取消点赞对收藏生效吗？** 不。收藏与点赞是两套关系，取消点赞仅提供于喜欢视图。
- **多账号怎么共用一份列表？** 「导出 / 导入」：A 账号导出 → 切到 B 账号导入（合并式，按内容去重）。
- **支持收藏夹（自建合集）吗？** 当前支持"收藏"整表（listcollection）；自建收藏夹的两级采集（先列夹再采夹内容）在路线图中。
